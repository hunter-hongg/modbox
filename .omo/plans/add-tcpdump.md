# add-tcpdump — Work Plan

## TL;DR (For humans)

**What you'll get:** A working `modbox tcpdump` command: live packet capture over Linux `AF_PACKET` raw sockets (no libpcap), classic pcap file read (`-r`, incl. stdin) and write (`-w`) that is byte-compatible with Wireshark, decoding of Ethernet II / ARP / IPv4 / IPv6 / TCP / UDP / ICMP / ICMPv6 into tcpdump-style one-line-per-packet output, a user-space capture-filter subset (`host`/`net`/`port`/`proto`/`src`/`dst` + `and`/`or`/`not` + parentheses), and display options `-q -v -e -x -tt -s` (`-n`/`-nn` accepted as no-ops). Plus a fully deterministic TDD test suite, man page, and README update.

**Why this approach:** Every implementation decision is locked by approved spec #102 and tickets #103/#106/#107/#108/#109. The repo precedent is "POSIX raw sockets + parse formats, zero new libraries" (ping, ss, lsof) — so AF_PACKET instead of libpcap, and a user-space filter instead of a BPF compiler. Tests are TDD at the existing CLI seam (`tests/test_tcpdump.sh`, auto-discovered): each todo adds failing bash assertions first, then implements to green; fixtures are pcap files generated in-test with `xxd -r -p`, so CI needs no network and no root.

**What it will NOT do:** no libpcap / no new Makefile dependencies; no pcapng; no BPF language (subset only); no DNS or service-name resolution; no promiscuous/monitor mode; no TUI; no 802.1Q/PPP/other linktypes (clean error); no `-ttt`; no touching of unrelated dirty worktree files.

**Effort:** ~8-12 hours for an agent worker. 4 waves, 15 TDD todos (each = failing test → implementation → green → commit).

**Risk:** Low-medium. The only genuinely new territory is AF_PACKET live capture, which is CI-safe by design (error paths + `-c`/summary logic tested through the `-r` path; privileged happy path documented for manual verification). Everything else follows repo precedent.

**Decisions:** TDD at bash CLI level (user-confirmed 2026-08-26); `-V`/`--version` for version because `-v` is verbose (dig precedent); summary line printed for both `-r` and live paths (real tcpdump also prints a summary on clean exit in read mode — tcpdump-conformant, not just a testability extension); `-w` writes filter-passing packets; `-r/-w` same file is an error; **exit codes: 0 = success, 1 = runtime errors (socket/file/pcap format), 2 = usage/parse errors (unknown option, bad filter expression) — repo convention (ping/arping/dig/jq/grep/fd/perf + their tests assert exit 2), refining spec #102 which said 1**; one Conventional Commit per todo.

## Scope

- **In scope (everything):** the 5 approved tickets — #103 scaffolding (command registration, `--help`/`-V --version`, man page, Makefile, README), #106 pcap reader + full decode chain, #107 filter subset + display options, #108 pcap writer + round trip, #109 AF_PACKET live capture (`-i`, `-c`, signals, summary, error paths). New/modified files: `include/commands/tcpdump.hpp` (new), `src/commands/tcpdump.cpp` (new), `tests/test_tcpdump.sh` (new), `docs/man/modbox-tcpdump.1.md` (new), `Makefile` (MAN_SOURCES +1 line), `tests/test_man_pages.sh` (+existence check), `README.md` (command list).
- **Out of scope / Must-NOT-Have (guardrails, from spec #102 Out of Scope):**
  - No `libpcap` and no change to `PKGS` in the Makefile. No BPF compiler, no full BPF language.
  - No pcapng; unsupported linktype → clean error, exit 1.
  - No DNS reverse lookup, no `/etc/services` parsing; output is always numeric; `-n`/`-nn` are accepted no-ops.
  - No promiscuous mode, no monitor mode, no kernel-side snaplen filtering.
  - No TUI mode, no `-ttt`/`-tttt`, no tshark-style features (JSON, protocol hierarchy, follow stream).
  - No deep application-layer decode (HTTP, DNS payload content — covered by existing `dig`/`nslookup`).
  - No IPv6 extension-header chains (fixed header + direct next 6/17/58 only; others → generic line).
  - No 802.1Q VLAN / PPP / raw IP / loopback link types.
  - Do NOT modify `tests/framework.sh` or `tests/run_tests.sh` (auto-discovery means no registration).
  - Do NOT touch unrelated dirty worktree files (e.g. `src/main.cpp`, `AGENT_CHANGELOG.md`, `.omo/run-continuation/*`) — stage only the 7 in-scope paths per commit.

## Verification strategy

- **TDD per todo (the backbone):** every todo first adds assertions to `tests/test_tcpdump.sh` that FAIL (`bash tests/test_tcpdump.sh` shows new FAIL lines — record expected red count), then implements, then `make && bash tests/test_tcpdump.sh` reaches zero FAIL. Implementation + its tests live in ONE todo.
- **Per-todo QA:** each todo below lists a happy QA invocation and a failure QA invocation, both agent-executable, with the exact expected evidence.
- **Wave boundaries:** after waves 1, 2, 3, 4 run the full suite `bash tests/run_tests.sh` — must exit 0 (zero regressions).
- **Determinism:** pcap fixtures are byte-constructed in-test (`xxd -r -p`); assertions use `-tt` (epoch timestamps from the fixture header) for exact values, and regex for the default `%H:%M:%S.uuuuuu` local-time form (value never asserted). No test touches the network or requires root (the EPERM path is asserted only when the test runs unprivileged).
- **Final verification wave:** F1-F4 all APPROVE (plan compliance, `make lint` quality, real manual QA, scope fidelity).
- **Tool preconditions (check once at start of T1):** `command -v xxd` and `command -v pandoc` succeed (both used by tests / man target); if `xxd` is absent, fall back to `printf` byte sequences for the same bytes.
